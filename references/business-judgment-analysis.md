# Business Judgment Analysis for Personal Knowledge Base

Use this guide when turning user-collected business materials into Obsidian notes. The material may be a meeting, transcript, interview, article, product analysis, investment discussion, founder story, customer conversation, training case, or business memo.

## Core Idea

This knowledge base is not a document archive. It is a training ground for the user's business judgment.

Every collected item should answer:

- Why did this feel worth saving?
- What does it change in the user's judgment?
- What business mechanism, relationship mechanism, opportunity signal, risk pattern, or reusable method is hidden inside?
- Which original details support that judgment?

Do not force every item into a meeting-review template. Select the analysis tools that fit the material. The goal is not to use every sophisticated section; the goal is to preserve the material's real value and then dig deep where the evidence supports it.

## Required Starting Point

For each item, first identify:

1. Material type: meeting, case, product article, interview, financing discussion, customer conversation, industry report, personal reflection, etc.
2. Why it was likely collected: opportunity, relationship, method, product insight, market signal, strategic story, risk, useful wording, personal resonance.
3. Best evidence base: transcript, original article, Get笔记 summary, or user-provided text.

If a transcript exists, analyze from the transcript. Get笔记 summaries are secondary references.

Before writing, use the semi-structured template workflow:

1. Identify the primary material type.
2. Start from that type's base skeleton in `Material-Type Skeletons`.
3. Fill only the tool slots supported by the source evidence.
4. Let the source's real value override section names and order when needed, but do not drift into a free-form structure without reason.
5. If no skeleton fits, build a custom structure from the same functions: why it matters, what happened, what must be preserved, what is really going on, what can be reused, and what evidence supports it.

## Semi-Structured Template Workflow

Use base skeletons for stability, and tool slots for intelligence. A skeleton is not a dead template: it defines the functional areas the note should cover. Tool slots such as `镜头`, `深水区`, `以案释法`, `QA 边界`, and `可沉淀工具` are filled only when the material supports them.

Rules:
- Start with the skeleton that best matches the primary material type.
- Do not create sections merely to show that a tool exists.
- Do not delete a high-value section from a skeleton unless the source clearly does not support it.
- Rename section headings to fit the material, but preserve the section's function.
- If a note has an existing high-quality structure, keep its insight density and only improve tool use around it. Do not replace a strong natural structure with mechanical tool headings.
- Multi-type materials should use one primary skeleton and borrow only the necessary slots from a secondary skeleton.

## Material-Type Skeletons

### Customer / Partnership / Sales / Project-Advancement Meeting

Use for customer calls, cooperation discussions, sales meetings, resource introductions, project kickoff or project advancement conversations.

Base skeleton:
- `为什么收录`
- `内容速写`
- `高价值发现`: usually 3-6 high-density findings. Name them as live business lenses such as `交易镜头`, `关系镜头`, `机会镜头`, `组织镜头`, `叙事镜头`, or better names that fit the material.
- `深水区`: choose supported scan items such as turning point, unspoken meaning, hidden door, identity shift, power/profit pool, counterfactual, boundary risk.
- `以案释法`: use when complete episodes teach reusable principles. No fixed count; include as many as are genuinely valuable and non-repetitive.
- `可迁移的方法`
- `风险和未验证点`
- `关键证据`
- `应进入哪些 Map`
- `暂不进入 Map 的内容` when there are tempting but low-value links or action-only details.

Default tool slots:
- `镜头` usually belongs inside `高价值发现` unless isolated scenes are clearer.
- `深水区` should preserve the dynamic movement of the relationship or opportunity.
- `以案释法` should follow complete episodes, not single quotes.

### Policy / Training / Guide / Expert Explanation

Use for policy interpretation, application rules, expert lectures, training sessions, guides, standards, product walkthroughs, or materials whose source structure matters.

Base skeleton:
- `为什么收录`
- `原始内容主线` / `政策主线` / `讲解结构`
- `核心规则 / 标准 / 条件`
- `QA 边界` or `例外与红线`: separate can do, cannot do, can do with evidence, high-risk / do not take.
- `关键镜头`: only Q&A or moments that reveal rule boundaries, hidden needs, or project opportunities.
- `以案释法`: no fixed count; use for complete reusable cases.
- `对项目的启发`
- `可沉淀工具 / 交付资产`
- `风险和误区`
- `关键证据`
- `应进入哪些 Map`

Priority: preserve the rule system and boundary cases before abstracting the business opportunity.

### Product / Delivery / Workflow Material

Use for product designs, implementation discussions, workflow redesign, system deployment, knowledge-base construction, automation, or delivery planning.

Base skeleton:
- `为什么收录`
- `场景与工作流复原`
- `用户真实任务`
- `痛点与瓶颈`
- `产品/交付机制`
- `最小可行切入点`
- `失败风险`
- `可沉淀工具 / 需求清单`
- `关键证据`
- `应进入哪些 Map`

Default tool slots:
- Use product, method, and risk lenses.
- Use `镜头` only when a concrete workflow moment reveals the real job-to-be-done or adoption barrier.
- Use `以案释法` for complete implementation cases or failure patterns.

### Business Opportunity / Industry / External Reference Material

Use for industry reports, market opportunities, public articles saved by the user, founder stories, investment discussions, competitor/product analysis, or broad strategic material.

Base skeleton:
- `为什么收录`
- `材料主张 / 原始论点`
- `机会判断`
- `客户 / 买方 / 预算`
- `交易结构`
- `竞争与风险`
- `对现有项目的影响`
- `可验证假设`
- `下一步实验`
- `关键证据`
- `应进入哪些 Map`

Default tool slots:
- Use opportunity, transaction, organization, narrative, risk, and method lenses as needed.
- Use `深水区` when the material reveals a non-obvious power/profit pool or hidden door.
- Use `以案释法` when a case teaches a transferable rule.

### Personal Reflection / Life Judgment

Use for personal reflections, relationship materials, life decisions, emotional judgment, learning notes, or self-understanding.

Base skeleton:
- `为什么收录`
- `原始情境`
- `触发点`
- `判断变化`
- `未说出口的东西`
- `可长期记住的句子`
- `以后遇到类似情况怎么做`
- `关键证据 / 原话`
- `应进入哪些 Map`

Default tool slots:
- Use self lens and narrative lens.
- Preserve exact wording when it carries emotional precision.
- Use `深水区` for unspoken meaning, identity shift, or boundary risk.
- Use `以案释法` when a personal episode teaches a future decision rule.

## Tool Slot Reference

These tools are optional and composable inside the skeletons. Use them when the material calls for them; omit them when they would add ceremony without insight.

### Original Structure Map

Use when the source is an explanation, policy training, guide, lecture, course, product walkthrough, or expert briefing.

Purpose:
- Preserve the source's own logic before interpreting it.
- Show the rule system, sequence, definitions, thresholds, categories, process, and exceptions.
- Make the note useful as a future reference, not only as an opinion piece.

Use it when:
- The material teaches a policy, procedure, framework, standard, product, market map, or technical system.
- The order of explanation matters.
- The value would be lost if only abstract insights were saved.
- The reader may later need to look up "what exactly were the rules?"

Do not use it when:
- The source is a loose conversation with no stable structure.
- The original structure is obvious and short enough to summarize in `内容速写`.

Good headings:
- `## 原始内容主线`
- `## 政策/规则主线`
- `## 讲解结构`
- `## 标准与条件`

### QA And Boundary Conditions

Use when the source contains Q&A, objections, exceptions, edge cases, eligibility questions, compliance boundaries, or "can this count?" discussions.

Purpose:
- Preserve the boundary cases where the real judgment lives.
- Convert rules into decision criteria.
- Separate "can do", "cannot do", "can do if evidence is supplied", and "high-risk / do not take" situations.

Use it when:
- The source includes live Q&A, support calls, policy interpretation, due diligence, legal/compliance-like reasoning, sales objections, customer qualification, or implementation troubleshooting.
- The value is in exceptions, red lines, gray zones, and proof requirements.
- The material can teach what not to sell, not only what to sell.

Suggested forms:
- `## QA 边界`
- `## 能申 / 不能申 / 可补材料 / 高风险`
- `## 例外与红线`
- `## 边界条件`

For policy or application materials, this tool is usually required. Do not collapse Q&A into generic risk reminders; Q&A often contains the actual operating logic.

### Scene Lens (`镜头`)

Use when a concrete moment reveals more than the surrounding summary.

Purpose:
- Preserve a vivid episode, question, objection, wording, hesitation, or reaction.
- Show how a rule, relationship, opportunity, or risk appears in real life.
- Train judgment through situated details, not only abstract conclusions.

Use it when:
- A person asks a practical question that exposes a hidden need, fear, loophole, or sales opportunity.
- A live answer clarifies the real policy/market boundary.
- A sentence changes the frame of the discussion.
- The original scene would help the user recognize a similar situation later.

Do not use it when:
- There is no meaningful scene, only a list of facts.
- The "scene" would merely quote a sentence without interpretation.

Suggested structure:

```markdown
## 关键镜头

### 镜头：国外模型购买到底认不认

**现场问题**：What was asked?
**表层答案**：What answer was given?
**真正说明的规则**：What business/policy logic does this reveal?
**对项目的启发**：How should the user act next time?
**证据**：Timestamped source link.
```

Usually 2-4 scenes are enough. Choose scenes that carry different lessons; do not list every Q&A item as a scene.

### Case Explanation (`以案释法`)

Use when one complete episode is valuable enough to teach a reusable business principle. This is stronger and more complete than `镜头`.

Purpose:
- Turn one concrete case into a transferable rule.
- Reconstruct context, action, reaction, turning point, and principle.
- Help the user make a future decision in a similar situation.

Use it when:
- There is a complete mini-case with setup, move, response, and consequence.
- The case teaches a negotiation move, qualification rule, product insight, relationship shift, compliance boundary, or risk pattern.
- The user could reuse the principle in future sales, consulting, product, policy, or partnership work.

Do not use it when:
- The material only contains isolated facts.
- A `镜头` is enough.
- There is no clear reusable "law" behind the case.

There is no fixed maximum count. Include every case that is genuinely valuable, evidence-backed, and non-repetitive. Stop when additional cases stop teaching a new transferable rule.

### Analysis Lenses

Use lenses when the material needs cross-sectional interpretation. Lenses are not sections that must all appear; they are ways to scan for value.

Use 2-4 lenses when:
- The material contains several kinds of value at once.
- You need to distinguish opportunity, transaction, relationship, product, organization, narrative, risk, method, or self-development.
- The source is rich enough that a single summary would flatten it.

Do not use lenses when:
- The source is primarily a rule/guide and needs `原始内容主线` + `QA 边界` first.
- The note would become a list of generic business categories.

### Deepwater (`深水区`)

Use when the material contains hidden value beneath the visible topic: turning points, unspoken motives, hidden doors, identity shifts, power/profit pools, counterfactuals, or boundary risks.

Use it when:
- The surface topic is not the real issue.
- A relationship, role, or opportunity changes underneath the conversation.
- The material has a non-obvious structural implication.
- The user would miss the value if the note stopped at facts and tools.

Do not use it when:
- The material is mainly a reference guide with little hidden social/commercial movement.
- The "deep" section would simply restate the main judgment.

### Action Assets

Use when the material should become an operating asset.

Purpose:
- Convert insight into checklists, scripts, templates, scorecards, qualification questions, playbooks, or next experiments.

Use it when:
- The material can directly improve a project, sales process, product, application workflow, training program, or client service.
- The user will likely reuse the output in future work.

Suggested headings:
- `## 可沉淀工具`
- `## 交付资产`
- `## 下一步实验`
- `## 问诊脚本`

## Fallback For Unmatched Materials

If no skeleton fits, do not force a bad match. Build a custom structure, but it must still satisfy these functions:
- why it matters
- what happened or what the original source says
- what original structure, boundary cases, or scenes must be preserved
- what is really going on beneath the surface
- what can be reused
- what risks or uncertainties remain
- what evidence supports it
- where it belongs in Maps

## Lens Reference

Choose only the lenses that fit. Usually 2-4 lenses are enough.

Lenses are cross-sectional. They look at the material from one angle, such as transaction, relationship, product, or risk.

### Opportunity Lens

Use when the material shows a new business opening.

Ask:
- What pain is becoming urgent?
- Who has budget, authority, or motivation?
- Why is the timing right now?
- What adjacent opportunity appears once the first need is accepted?

### Transaction Lens

Use when the material involves deals, pricing, contracts, pilots, services, financing, or conversion.

Ask:
- How is value packaged so the other side can buy it?
- How is risk reduced?
- What is the smallest credible first transaction?
- What moves the discussion from idea to commitment?

### Relationship Lens

Use when trust, alliance, customer psychology, status, authority, or cooperation matters.

Ask:
- What did the other person actually care about?
- Where did the emotional temperature change?
- What made the other side feel safer, bigger, respected, or more in control?
- Did the relationship move from vendor/customer to partner/alliance?

### Product Lens

Use when the material reveals a product, workflow, user need, or implementation pattern.

Ask:
- What job is the product really doing?
- What part of the workflow is painful enough to automate?
- What is the adoption wedge?
- What must be simple first before it can become powerful?

### Organization Lens

Use when the material involves companies, associations, governments, teams, incentives, processes, or internal capability.

Ask:
- Who must change behavior?
- What incentive or fear blocks adoption?
- What capability must be built inside the organization?
- What role can the user or project occupy in the organization?

### Narrative Lens

Use when persuasion, framing, storytelling, policy language, or category creation matters.

Ask:
- What wording made the idea legible?
- How was a technical idea translated into a business or status opportunity?
- What story made the listener feel this was their opportunity?
- What phrase or frame is reusable?

### Risk Lens

Use when the material may contain false opportunity, unclear buyer, execution burden, compliance risk, trust risk, or overreach.

Ask:
- What could be fake demand?
- What is being assumed but not proven?
- Where can the project become too big, too vague, or too expensive?
- What evidence would make the risk smaller?

### Method Lens

Use when the material contains reusable tactics, frameworks, scripts, workflows, or decision rules.

Ask:
- What can be reused next time?
- What sequence worked?
- What question unlocked the situation?
- What operating principle should be saved?

### Self Lens

Use when the material should train the user's own business instincts.

Ask:
- What should the user do differently after reading this?
- What ability does this remind the user to build?
- What blind spot does it expose?
- What kind of future situation will this help with?

## Deepwater Section

Use `深水区` as the main place for the material's hidden value. This section should be more detailed than ordinary lens findings when the material contains an important turn, unspoken motive, hidden opportunity, relationship shift, or structural risk.

Do not add many new top-level sections. Keep one `## 深水区` section after `## 高价值发现` and before `## 以案释法`. Treat the following as scan items under that section. Include only the scan items that are actually supported by the transcript/source; omit the rest.

`深水区` is not a summary. It should answer: what is really changing underneath the visible topic, what door has opened, and what evidence proves the door is open.

### Deepwater Scan Items

#### Turning Point

Use when the emotional, commercial, or strategic direction changes.

Ask:
- When did the conversation stop being ordinary information exchange?
- Which sentence, question, or reaction changed the other side's posture?
- Did someone move from defense to initiative, from buyer to partner, from listener to co-designer?
- What became possible after this turn that was not possible before?

#### Unspoken Meaning

Use when the important signal is implied rather than directly stated.

Ask:
- What fear, desire, ambition, or constraint is the other side showing without naming it?
- What are they protecting: budget, authority, face, internal control, data, status, or future optionality?
- What does a practical question really reveal underneath?
- Which repeated concern deserves interpretation rather than literal treatment?

#### Hidden Door

Use when the surface topic reveals a larger opening.

Ask:
- What is the apparent topic, and what is the larger opportunity behind it?
- Does a small project open a path to training, standards, policy, distribution, certification, financing, or long-term service?
- Which adjacent opportunity appears only after the first need is accepted?
- What should be tested next to see whether the door is real?

#### Identity Shift

Use when a person or organization changes role.

Ask:
- What role did each side occupy at the start: buyer, vendor, expert, sponsor, channel, evaluator, operator?
- What role did they begin to occupy later?
- Did the customer start imagining themselves as organizer, standard setter, industry node, or joint service provider?
- Did the user's side move from delivery vendor to translator, operator, partner, or infrastructure builder?

#### Power And Profit Pool

Use when money, authority, ownership, or distribution is underneath the surface.

Ask:
- Who has budget, mandate, distribution, official backing, data, trust, or customer access?
- What existing profit pool might the new AI/product/service protect, expand, or damage?
- Who might resist the change because it threatens their original value?
- What must be written into the deal: ownership, revenue share, authority, responsibility, data rights, identity use, or case rights?

#### Counterfactual

Use to distinguish what actually unlocked value from what merely happened nearby.

Ask:
- If this sentence/action had not happened, where would the conversation likely have stopped?
- If the risk-reduction move had not been made, would the later excitement have appeared?
- Which part was necessary but not sufficient, and which part was the actual unlock?
- What false lesson would someone learn if they only looked at the surface outcome?

#### Boundary Risk

Use when excitement may hide later conflict.

Ask:
- What became bigger than the current contract, scope, or capability?
- Which responsibilities, identities, data rights, or revenue expectations are still vague?
- Where can a relationship upgrade create liability or delivery pressure?
- What must be clarified before the opportunity is pursued further?

### Deepwater Writing Standard

For each included scan item:
- Name the scan item in the subheading, for example `### 转折点：从采购审查到共同想象生意`.
- Start with the deep judgment, not the facts.
- Reconstruct the specific sequence that supports the judgment.
- Link to exact evidence when a transcript/source exists.
- End with one reusable implication or next action when appropriate.

Good:

```markdown
## 深水区

### 转折点：客户开始替我们设计生意

真正的变化不是客户说“感兴趣”，而是他开始问培训能不能盈利，并主动把服务、政策文件和全国推广接起来。这说明他已经不再只是在评估供应商，而是在把项目放进自己的行业组织者身份里。

证据：
- [[Transcript#^t002045|00:20:45]]：客户问这个东西能不能盈利。
- [[Transcript#^t003221|00:32:21]]：客户提出互用身份对外服务。

下次遇到协会/园区客户，要准备能让对方继续想下去的业务锚点：谁组织、谁付钱、谁背书、谁能对外讲。
```

Avoid:
- Listing every scan item even when unsupported.
- Repeating the same content already covered in `高价值发现`.
- Using vague words such as "important", "interesting", or "有价值" without naming what changed.
- Treating a positive meeting atmosphere as evidence by itself.

## Case Explanation Writing Standard

Use `以案释法` when one complete segment is valuable enough to teach a business principle. This is different from a lens:

- A lens is a slice across the whole material.
- `以案释法` follows one concrete episode from context, action, reaction, turning point, to reusable rule.

Use `以案释法` when:
- A transcript segment shows a complete move, not just a single quote.
- The sequence matters: what happened before and after changes the interpretation.
- There is a clear business lesson, negotiation move, relationship shift, product insight, or risk pattern.
- The user could reuse the move in a future situation.

Suggested structure:

```markdown
## 以案释法

### 案例：一句“能不能盈利”背后的关系转折

**场景**：What was happening before the segment?

**动作**：What did someone say or do?

**反应**：How did the other side respond?

**转折**：What changed in the relationship, opportunity, or framing?

**背后的法**：What principle does this episode teach?

**下次怎么用**：How should the user reuse this?

**证据**：Timestamped transcript links.
```

Do not overuse it, but do not impose a fixed count. Include every evidence-backed case that teaches a distinct transferable rule; stop when additional cases become repetitive or stop changing the user's judgment.

## Highlighting Standard

Use bold or callout-style emphasis sparingly. Highlight only what should survive a quick skim.

Highlight these:
- The core judgment of why the item matters.
- A turning point in the material.
- A reusable principle or method.
- A non-obvious risk or hidden assumption.
- A sentence the user should remember or reuse.

Do not highlight:
- Ordinary facts, dates, names, and logistics.
- Every section heading's first sentence.
- Generic business cliches.
- Anything unsupported by transcript/source evidence.

Default style:
- Use `**bold**` for compact key judgments.
- Use blockquotes for high-value principles or memorable reusable formulations.
- Avoid excessive highlighting; if more than 20-25% of a section is bold, the emphasis has failed.

## Main Note Shape

Keep the required Obsidian properties/frontmatter at the top. Do not add a duplicated H1 title or a duplicated `基本信息` table in the body. The filename should carry the date and title. After the properties, use a flexible structure:

For insight notes based on transcripts or original source files, include one `原始材料` property linking to that transcript/source. Do not rely only on timestamp links inside the body. Do not duplicate semantically identical fields such as `原始文件`, `原文来源`, and `完整转录`; use a single `原始材料` field unless they point to genuinely different files.

Evidence rule: every timestamp cited in `证据`, `关键证据`, `镜头`, or `以案释法` must link to the exact transcript/source segment with an Obsidian block link, for example `[[Transcript File#^t002045|00:20:45]]`. Add timestamp-derived block ids to the transcript first. A bare timestamp is not enough because it cannot carry the reader back to the original wording.

Do not treat the following shape as a required template. It is a menu of functions. Pick the sections that preserve the source's value and serve the user's future work.

```markdown
## 为什么收录

This is not a summary. State the value of saving this item.

## 内容速写

Briefly reconstruct the situation in a few lines.

## 原始内容主线

Use for policy, training, guide, lecture, product walkthrough, or expert explanation materials. Preserve the rule system, process, categories, thresholds, and key definitions before interpreting them.

## QA 边界 / 例外与红线

Use when the source contains Q&A, objections, exceptions, eligibility conditions, compliance-like reasoning, or "can this count?" situations. Separate what can be done, cannot be done, can be done with evidence, and should not be sold.

## 高价值发现

Use selected lenses. Each finding should include interpretation, not just facts.

## 深水区

Use this as the most detailed section when the material contains hidden value: turning points, unspoken motives, hidden doors, identity shifts, power/profit pools, counterfactuals, or boundary risks. Include only supported scan items.

## 关键镜头

Use concrete scenes when a moment, question, objection, or live answer reveals a rule, opportunity, hidden need, or risk. Interpret the scene; do not merely quote it.

## 以案释法

Use complete episodes when transcript/source segments teach reusable principles. There is no fixed count; include every evidence-backed case that teaches a distinct transferable rule.

## 可迁移的方法

Extract reusable principles, moves, prompts, questions, or warning signs.

## 可沉淀工具 / 交付资产

Use when the material can become a checklist, script, template, scorecard, playbook, qualification form, or next experiment.

## 关键证据

Link to transcript/source and include timestamp or location when available.

## 应进入哪些 Map

Only link stable long-term topics/projects.
```

Use different headings when the material needs them, but preserve the function:
- why it matters
- what happened
- what original structure and boundary cases must be preserved
- what is really going on
- what can be reused
- what evidence supports it

## Evidence Style

Evidence should be precise enough to trace, but not a giant quote dump.

Good:

```markdown
- 00:20:45：对方把培训问成“能不能盈利”，说明话题从项目交付进入业务化可能。
- 00:32:21：对方提出互用身份对外服务，关系从甲乙方转向联盟。
```

Avoid:

```markdown
这场会议很重要，因为大家聊得很好。
```

## What Not To Do

Avoid:

- Turning every meeting into the same rigid review template.
- Treating Get笔记 summary as the final note.
- Extracting only quotes and to-dos.
- Creating many backlinks before there is a judgment to connect.
- Writing business cliches without transcript evidence.
- Making the note so abstract that the original situation disappears.

## Default Policy for Get笔记 Rebuilds

- Do not generate Source files by default if they only duplicate Get笔记 summaries.
- Keep Transcript files when available; they are valuable evidence.
- Build main notes from transcript analysis where possible.
- Put Get笔记 AI summary at the end only if useful, or omit it from the main note.
- Keep Map links sparse and judgment-driven.
